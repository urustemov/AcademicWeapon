# Academic Weapon — локальная демонстрационная версия

**Academic Weapon · AUCA Academic Advising Center**

Сайт запускается **локально на вашем компьютере**. Хостинг, домен и облачная база данных сейчас **не нужны**. Начальная база содержит исключительно вымышленных студентов, аккаунты и академические показатели.

## Быстрый запуск на Windows

1. Скачайте архив `Academic_Weapon_Local.zip`, распакуйте его в обычную папку, например `Документы\Academic_Weapon_Local`.
2. Установите **Python 3.11 или новее** с [python.org/downloads](https://www.python.org/downloads/). При установке отметьте **Add Python to PATH**, если доступно.
3. Дважды нажмите **`run_windows.bat`**. При первом запуске потребуется интернет для установки Python-библиотек; установку автоматизирует файл `.bat`.
4. Откройте в браузере **http://127.0.0.1:8000** (скрипт попробует открыть страницу самостоятельно).
5. Оставьте окно запуска открытым во время работы. Чтобы остановить сервер, закройте окно или нажмите Ctrl+C.

При следующих запусках используйте тот же `run_windows.bat`. Ваша демонстрационная база сохранится между перезапусками.

## Вход студентов через Google AUCA

В проекте подготовлен вход через Google Identity Services. Сервер принимает только подтверждённую Google Workspace-учётную запись домена `auca.kg`, после чего дополнительно проверяет, что адрес есть в импортированном текущем списке Academic Probation. Адрес домена сам по себе доступ не даёт.

1. В Google Cloud Console создайте **OAuth client ID → Web application**.
2. Для локальной проверки добавьте origin `http://127.0.0.1:8000` и URI `http://127.0.0.1:8000/auth/google`. Для опубликованного сайта добавьте точный HTTPS-адрес.
3. Скопируйте `.env.example` в `.env` и замените пример в `GOOGLE_CLIENT_ID` на Web Client ID. Client Secret этому способу входа не требуется и в проект сохраняться не должен.
4. Перезапустите приложение. На странице входа появится официальная кнопка Google.

Google-вход проверяет подпись и срок действия ID token, `aud`, подтверждённую почту и Workspace claim `hd=auca.kg`. Учётная запись связывается со студентом только после совпадения с разрешённым адресом в базе.

## Безопасная синхронизация списка Academic Probation

Скрипт `import_students.py` читает только актуальный лист `Academic Probation (62)`. По умолчанию он выполняет проверку без изменения базы:

```bash
python import_students.py "/путь/к/Academic Probation_AAC working list.xlsx"
```

После успешной проверки импорт в отдельную рабочую базу запускается явно:

```bash
python import_students.py "/путь/к/Academic Probation_AAC working list.xlsx" \
  --db academic_weapon.sqlite3 --apply --deactivate-missing
```

Синхронизируются только Student ID, ФИО, `@auca.kg` email, программа, год обучения и CGPA. Телефоны, комментарии, история контактов, counseling и другие чувствительные колонки намеренно не импортируются. Повторный запуск обновляет записи по Student ID; отсутствующие студенты при флаге `--deactivate-missing` деактивируются без удаления истории.

Файл Excel, `.env` и рабочую SQLite-базу нельзя добавлять в GitHub. Перед настоящим использованием требуется HTTPS-развёртывание, согласование AUCA IT и проверка безопасности/правил хранения данных.

## Что уже работает

**Student Portal:** личный Dashboard, просмотр академических целей и плана, отметка выполненных задач, Weekly Check-in, запрос поддержки AAC, расписание встреч и раздельные чаты с личным Advisor и участниками Advising Team.

**Staff Portal:** три уровня доступа — Student видит только собственную запись, Advisor только назначенных ему advisees, Advising Team всех студентов и все разрешённые диалоги. Доступны Dashboard, список/поиск/фильтр студентов, профили, цели, статусы кейсов сопровождения, встречи, follow-ups, check-ins и журнал действий.

**Интерфейс:** адаптация под телефон, переключение светлой/тёмной темы, тестовые данные в SQLite, отсутствие необходимости покупать хостинг.

## Где хранятся данные

Локальная база SQLite создаётся автоматически при запуске в файле `apss_demo.sqlite3` в папке проекта. Локальный ключ сессий хранится в `.apss_local_secret`. Не публикуйте эти файлы. При копировании проекта для другого человека лучше НЕ включать их в архив.

Файл `reset_demo_data.bat` восстанавливает исходные вымышленные записи и стирает все изменения, сделанные в демоверсии. Перед сбросом закройте приложение.

## Ограничения и безопасность

- Локальный сервер привязан к **127.0.0.1**, поэтому по умолчанию доступен только на этом компьютере.
- Приложение реализует **демонстрационное разграничение ролей**, но не имеет производственной системы безопасности, развернутых проверок на все угрозы и полноценного управления пользователями.
- **Никогда не загружайте в этот прототип настоящие ФИО, Student ID, оценки, письма, контакты, заметки консультаций.**
- Начальные студенты созданы исключительно для тестирования. `example.com` / `demo.example` используются как фиктивные адреса.
- После первоначальной установки Python-библиотек интерфейс и база могут работать без интернета; шрифты используют системные варианты.

## Для разработчика

```bash
python -m venv .venv
# activate the environment
pip install -r requirements.txt
python app.py
```

В основе Python FastAPI + Jinja2 + SQLite. Этот выбор позволяет создавать настоящую локальную базу и backend без отдельной установки PostgreSQL или Node.js. В дальнейшем архитектуру можно расширить и развернуть на сервере после отдельной работы по безопасному запуску.

### Тесты для дальнейшей разработки

После установки библиотек можно установить `requirements-dev.txt` и выполнить `pytest tests/ -q`. Тесты работают с отдельной временной базой и не изменяют ваши данные.
