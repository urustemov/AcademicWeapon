# Academic Weapon

Веб-платформа AUCA Academic Advising Center для сопровождения студентов,
находящихся на academic probation. Система объединяет рабочие планы,
еженедельные check-in, встречи, расписание, уведомления и приватное общение со
своим advisor или участником Advising Team.

## Статус проекта

Проект находится на стадии защищённого пилота.

| Компонент | Текущее состояние |
|---|---|
| Backend | FastAPI, Python 3.15 |
| Интерфейс | Jinja2, HTML, CSS и JavaScript |
| Пилотная база | SQLite на постоянном зашифрованном диске Render |
| Хостинг | Render, регион Frankfurt |
| Технический адрес | `https://academic-weapon-staging.onrender.com` (перенаправляется) |
| Официальный адрес | `https://advising.auca.kg` |
| Аутентификация | Google Workspace AUCA и серверный список разрешённых аккаунтов |

Репозиторий не содержит рабочую базу студентов, таблицы импорта, ключи сессий
или иные секреты. Перенос реальных данных выполняется отдельно по защищённому
каналу после проверки окружения.

## Модель доступа

- **Student** видит только собственный профиль, план, расписание, check-in,
  встречи, уведомления и свои приватные диалоги.
- **Advisor** видит только назначенных ему advisees и связанную с ними
  разрешённую рабочую информацию.
- **Advising Team** управляет всеми студенческими кейсами и координирует
  advisors. Приватные переписки других участников этой роли не раскрываются.

Домен `auca.kg` сам по себе не предоставляет доступ. После проверки Google
ID token сервер дополнительно требует активную запись пользователя в локальном
списке доступа.

## Основные функции

- каталог студентов с поиском и фильтрами по department и class standing;
- профили, academic goals, follow-up tasks и статусы сопровождения;
- недельное расписание курсов и встреч;
- назначение и изменение advising appointments с проверкой полномочий;
- weekly check-in с заданным временным окном и напоминаниями;
- приватные диалоги Student–Advisor, Student–Advising Team, личные служебные
  диалоги и закрытый групповой чат четырёх участников Advising Team;
- уведомления и журнал действий с разграничением видимости по ролям;
- встроенный AAC Tracker для Advising Team: dashboard, регистрация визитов,
  история студентов, follow-ups и отчёты с записью в утверждённую Google Sheet;
- импорт ограниченного набора данных из утверждённого Excel-файла.

## Защита данных

Production-конфигурация включает:

- обязательный HTTPS и HSTS;
- cookies `Secure`, `HttpOnly` и `SameSite=Lax`;
- Content Security Policy и дополнительные security headers;
- проверку подписи, срока действия, audience и hosted domain Google ID token;
- allowlist пользователей и серверное разграничение ролей;
- ограничение частоты попыток входа;
- закрытые страницы API-документации;
- отдельный `/healthz` без пользовательских данных;
- принудительное перенаправление технического Render-адреса на официальный домен;
- хранение секретов только в переменных окружения Render;
- серверный ключ связи AAC Tracker, который не передаётся браузеру;
- исключение `.env`, SQLite-баз, таблиц импорта и локальных ключей из Git.

SQLite с одним экземпляром сервера предназначена для ограниченного пилота.
Перед широким production-запуском требуется миграция в управляемую PostgreSQL,
формальная политика хранения данных и независимая проверка безопасности.

## Локальная среда разработки

Требуется Python 3.15. Значения конфигурации документированы в
`.env.example`; рабочий `.env` не должен попадать в Git.

```bash
python3.15 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

По умолчанию приложение доступно только на `http://127.0.0.1:8000`.
Демонстрационный режим предназначен исключительно для локальной разработки и
принудительно запрещён в production.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest tests/ -q
```

Тесты используют временную базу и не изменяют рабочие данные.

## AAC Tracker

Tracker отображается непосредственно в портале и доступен только роли
`advising_team`. Браузер обращается только к FastAPI; сервер повторно проверяет
роль и CSRF, после чего вызывает закрытый JSON-мост Apps Script. Исходная Google
Sheet остаётся источником данных, поэтому новые визиты и статусы продолжают
появляться в ней. Код моста и инструкция находятся в
`integrations/aac_tracker/`.

## Резервное копирование

`backup_database.py` создаёт согласованный snapshot работающей SQLite-базы,
проверяет его через `PRAGMA integrity_check` и хранит файлы с правами только для
владельца. Для production команда выполняется в защищённом Render Shell:

```bash
python backup_database.py --source /var/data/academic_weapon.sqlite3 \
  --output-dir /var/data/backups --keep 14
```

Проверка конкретной копии без восстановления:

```bash
python backup_database.py --verify-only /var/data/backups/ИМЯ_ФАЙЛА.sqlite3
```

Копия на том же диске защищает от случайного изменения базы, но не от потери
самого диска. Для пилота проверенный файл также регулярно выгружается в
одобренное AUCA IT защищённое хранилище; GitHub и электронная почта не подходят.

## Импорт студентов

`import_students.py` обрабатывает только утверждённый лист Academic Probation и
по умолчанию выполняет проверку без записи. Импортируются Student ID, ФИО,
AUCA email, программа, class standing и CGPA. Телефоны, counseling notes,
история контактов и другие чувствительные поля намеренно исключены.

```bash
python import_students.py "/secure/path/Academic Probation list.xlsx"
```

Применение проверенного импорта выполняется только к явно указанной базе:

```bash
python import_students.py "/secure/path/Academic Probation list.xlsx" \
  --db /secure/path/academic_weapon.sqlite3 --apply --deactivate-missing
```

Исходный Excel-файл и полученная база не передаются через GitHub или обычную
электронную почту.
