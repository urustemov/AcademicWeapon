# Academic Weapon: безопасный staging на Render

Эта инструкция создаёт закрытую тестовую интернет-версию приложения. Не
загружайте рабочую базу студентов до завершения проверки входа и прав доступа.

## Что уже подготовлено

- Python закреплён на версии 3.15.0.
- Render запускает один экземпляр FastAPI через HTTPS-прокси.
- SQLite хранится на постоянном зашифрованном диске `/var/data`.
- Ключ сессий генерируется Render и не хранится в GitHub.
- Локальный вход по паролю и демонстрационные кнопки отключены в production.
- Разрешён только Google-вход с подтверждённым доменом `auca.kg`.
- Включены защищённые cookies, HTTPS, security headers и ограничение попыток входа.
- Render проверяет состояние приложения через `/healthz`.

## Шаг 1. Отправить подготовленные изменения в GitHub

После финальной проверки создайте commit и отправьте ветку `main` в репозиторий
`urustemov/AcademicWeapon`. Файлы `.env`, `academic_weapon.sqlite3` и
`.apss_local_secret` игнорируются Git и не должны появиться в репозитории.

## Шаг 2. Создать Render Blueprint

1. Откройте <https://dashboard.render.com/> и войдите через GitHub.
2. Нажмите **New → Blueprint**.
3. Подключите репозиторий **urustemov/AcademicWeapon**.
4. Render найдёт файл `render.yaml`.
5. В поле `GOOGLE_CLIENT_ID` вставьте только Web Client ID Google. Client Secret
   этому приложению не требуется.
6. Подтвердите создание Blueprint. Будет создан платный Web Service с постоянным
   диском. До подтверждения внимательно проверьте показанную Render стоимость.
7. Дождитесь статуса **Live**. Первый запуск создаст пустую защищённую базу и
   подготовит разрешённые Google-only аккаунты Advisors и Advising Team.

## Шаг 3. Настроить Google-вход для staging

1. Скопируйте адрес Render, например
   `https://academic-weapon-staging.onrender.com`.
2. Откройте Google Cloud Console → Google Auth Platform → Clients.
3. Откройте существующий Web Client Academic Weapon.
4. В **Authorized JavaScript origins** добавьте адрес Render без завершающего
   слеша.
5. В **Authorized redirect URIs** добавьте адрес с путём `/auth/google`, например
   `https://academic-weapon-staging.onrender.com/auth/google`.
6. Сохраните изменения и подождите несколько минут.

## Шаг 4. Первый тест без рабочей базы студентов

1. Откройте адрес Render в отдельном приватном окне браузера.
2. Войдите под одним из аккаунтов Advising Team.
3. Убедитесь, что URL начинается с `https://` и браузер не показывает
   предупреждение о сертификате.
4. Проверьте выход из аккаунта и повторный вход.
5. На этом этапе отсутствие студентов является нормальным: рабочая база ещё не
   переносилась.

## Шаг 5. Контрольная проверка с IT Department

До переноса данных IT должен проверить:

- Google-вход и запрет неизвестных аккаунтов;
- права Student, Advisor и Advising Team;
- конфиденциальность чатов;
- невозможность Advisor открыть чужого студента;
- защищённые cookies и security headers;
- резервное копирование и восстановление постоянного диска;
- журнал Activity Log без токенов, паролей и содержимого приватных сообщений.

## Шаг 6. Перенос данных

После успешной проверки создайте резервную копию локальной базы и перенесите её
на постоянный диск Render через защищённое подключение. Не добавляйте базу в
GitHub и не отправляйте её по обычной электронной почте. После переноса снова
проверьте три роли и только затем выдавайте ссылку студентам.

SQLite и один экземпляр сервера подходят для ограниченного пилота. Перед
полноценным масштабированием нужно отдельно перенести данные в управляемую
PostgreSQL с автоматическими резервными копиями.
